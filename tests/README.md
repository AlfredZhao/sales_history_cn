# 促销生成回归测试

## 离线测试

在仓库根目录运行（仅 Python 标准库，不需要数据库）：

```bash
python3 -m unittest discover -s tests -v
```

覆盖自然月活动窗口、起止边界、闰年、未来日期、单日范围、追加不改历史候选集、分段一致性、编号上界、年度行数，以及初始化/追加共用生成器的源码接线。

这些是**参考算法与静态检查**，不执行 Oracle SQL，也不模拟 `ORA_HASH`，不能代替数据库回归。

## Oracle 回归

准备一个**专用的空测试 schema**（AL32UTF8），具备 `CREATE SESSION`、`CREATE TABLE`、`CREATE PROCEDURE` 权限及测试表空间配额。禁止使用业务 schema、现有 SH 或管理账号。

在 SQLcl 中以该测试用户连接后，从仓库根目录执行：

```sql
@tests/oracle_promotion_generation.sql
```

脚本先检查 schema 为空，再创建最小表结构并安装实际 `SH_DATA_GENERATION` 包，验证：

- 实际 SQL 编译、日期候选筛选、SALES/COSTS 有效期；
- 一次性生成与跨年、月中、闰日分段生成的逐行多重集一致性；
- 无促销标价、普通短期活动、成本组合唯一性与覆盖；
- 日期越界、孤立促销引用、倒置区间、错误的无促销有效期、缺失日期/销售均被拒绝；
- 无有效候选时不能静默生成 0 行；包内无提交，调用方可以完整回滚；
- 完整闰年恰好 200,000 条销售，以及未来单日范围。

测试数据 DML 在结束时回滚，**DDL 创建的测试表和包仍保留**；请按本地规则清理专用测试 schema，不要在实际 SH 上运行此脚本。再次执行需换用空 schema。此测试不执行完整安装、SQLcl CSV 装载或物化视图刷新；最终仍需在目标 Oracle 环境重新初始化并检查安装日志。
