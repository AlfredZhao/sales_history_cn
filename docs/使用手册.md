# SH 中文化样例数据使用手册

本项目用于个人测试和 PoC：在保留 Oracle SH 标准英文对象名的前提下，装载中文化维度数据，并按安装参数生成可复现的销售历史数据。

## 1. 前置条件

- Oracle Database 19c 或更高版本，数据库字符集为 `AL32UTF8`。
- SQLcl 26.1.2.0 或更高版本。
- 使用具备创建、删除用户权限的账号连接，例如 `SYSTEM` 或 `ADMIN`。
- 从仓库内的 `sales_history_cn/sales_history` 目录执行脚本；该目录下的 CSV 文件必须完整保留。

> 注意：若输入 `YES` 覆盖已有 SH 模式，安装脚本会执行 `DROP USER SH CASCADE`。这会永久移除该用户及其对象，请勿对承载业务数据的 SH 用户执行。

## 2. 安装

在终端中进入脚本目录并连接目标数据库：

```bash
cd sales_history_cn/sales_history
sql system@//db-host:1521/service_name
```

在 SQLcl 中运行：

```sql
@sh_install.sql
```

安装依次询问 SH 密码、表空间、生成模式及该模式需要的参数，然后询问是否覆盖已有 SH 模式。`RECENT` 只询问完整自然年数，`RANGE` 只询问起止日期。脚本会在当前目录生成 `sh_install.log`。

### 默认方式：最近 N 个完整自然年加今年截至当天

输入示例：

```text
生成模式 [RECENT|RANGE] [RECENT]: RECENT
RECENT 模式的完整自然年数 [3]: 3
```

其中“当天”取目标数据库服务器的 `SYSDATE`。例如服务器日期为 `2026-09-09`、N 为 3 时，请求范围为 `2023-01-01` 至 `2026-09-09`。

### 自定义方式：指定起止日期

输入示例：

```text
生成模式 [RECENT|RANGE] [RECENT]: RANGE
RANGE 模式起始日期 (YYYY-MM-DD): 2025-07-01
RANGE 模式结束日期 (YYYY-MM-DD): 2030-12-31
```

`RANGE` 的起止日期均包含在最终范围内，可指定未来日期。

## 3. 追加生成数据

首次安装完成后，如需将事实数据从已有最大日期扩展至某个更晚的日期，请以 `SH` 用户连接，并在 `sales_history_cn/sales_history` 目录执行：

```sql
@sh_append.sql
```

脚本默认目标结束日期为目标数据库服务器当天，也可输入未来日期。它**不会询问起始日期**，而是自动以 `MAX(TIMES.TIME_ID) + 1` 作为起点，因此只能连续向后追加，不能重复插入或覆盖既有日期。

例如，现有数据最大日期为 `2026-09-01`，输入目标结束日期 `2026-09-28` 时，实际新增范围为 `2026-09-02` 至 `2026-09-28`，不会再次生成 `2026-09-01`。若目标结束日期不晚于当前最大日期，脚本不写入数据并记为 `SKIPPED`。

追加时，脚本会：

- 检查 `TIMES` 日期范围连续性、`SALES`/`COSTS` 日期覆盖一致性和必需维度；
- 锁定 `TIMES`，阻止两个追加会话并发执行；
- 补齐新增范围涉及月份的促销活动，不修改历史活动编号或有效期；
- 生成新增范围的 `TIMES`、`SALES`、`COSTS`，刷新物化视图并收集相关统计信息；
- 在刷新物化视图和提交前强制检查促销有效期、日期覆盖及每日销售行数，失败时回滚本次生成；
- 自动创建并维护 `SH_GENERATION_LOG`，记录 `RUNNING`、`SUCCESS`、`SKIPPED` 或 `FAILED` 状态。

可查询追加记录：

```sql
SELECT run_type, status, requested_start, requested_end,
       sales_rows, costs_rows, started_at, finished_at, error_message
FROM sh_generation_log
ORDER BY started_at DESC;
```

`sh_append.sql` 不支持补历史缺口或覆盖已有日期；这类操作应使用经过备份和人工确认的专门重建脚本，不能将其与安全追加混用。

本版促销生成逻辑需要通过 `sh_install.sql` 重新初始化，不能只把新版追加脚本用于旧 SH 数据。初始化会安装共享的 `SH_DATA_GENERATION` 包。

## 4. 生成规则

- 客户和补充人口统计维度从 CSV 装载；`PROMOTIONS`、`TIMES`、`SALES` 和 `COSTS` 在选定范围内生成，不再装载其原始 CSV。旧 `promotions.csv` 仅保留为参考，不参与初始化。
- `SALES` 每个完整自然年约 200,000 行，不完整年份按实际天数比例生成。最终 `MIN(time_id)` 和 `MAX(time_id)` 与选定范围一致。
- `COSTS` 按产品、日期、促销和渠道的唯一组合生成，避免多笔销售造成重复成本行。
- 固定随机种子为 `20260909`。在 CSV、脚本版本和输入参数一致时，生成的新增事实数据一致。
- `TIMES` 使用中国自然日历：周一为首日，周日为周结束日；财年、财月、财季等同自然年口径。时间文本格式示例：`2026年09月`、`2026年Q3`、`星期一`。
- `SALES` 和 `COSTS` 使用按年自动扩展的 interval 分区，因此生成到未来年份不需要再修改建表 DDL。

### 促销有效期与销售关联

- 每个涉及的自然月生成 3 个独立活动：会员优惠为 **1–14 日**，线上优惠为 **8–21 日**，月末优惠为 **18 日至月末**，起止日期均包含当天。名称仅为模拟活动类型，不表示实际节假日。
- 活动编号及完整有效期只依赖年月和活动类型，不受安装起止日期影响。即使只生成某月一天，也创建该月的完整活动窗口；同月追加不会缩短或延长已有窗口，跨月追加只补建新活动。
- `PROMO_ID=999` 始终表示“无促销”，成本为 0，技术有效期为 `0001-01-01` 至 `9999-12-31`，不是跨越多年的真实活动。无促销销售按商品标价生成，不使用促销折扣。
- 每笔销售使用固定种子，从**销售当日有效的活动与无促销记录**中选择；普通促销销售仍采用模拟的 70%–95% 标价系数，并非真实营销效果模型。
- 新初始化的促销总数为 `涉及月份数 × 3 + 1`，不再固定为 503。每个完整自然年仍生成 200,000 条销售，日期筛选不会减少目标行数。
- 初始化和追加共用生成规则。在其他维度不变的前提下，一次性生成与连续分段追加的事实数据一致；追加不会修改历史促销或事实数据。

## 5. 中文化范围

数据库对象名保持 Oracle SH 的英文命名，以兼容标准示例 SQL。装载后，以下展示数据会被中文化：

- 国家和区域名称；客户姓名、地址、电话、邮箱、收入与婚姻状态。
- 产品的单位、包装、状态和汇总描述。
- 促销名称、类别、子类别与汇总描述。
- 补充人口统计中的教育、职业、家庭规模和备注。
- `TIMES` 的星期、月、季及财务期间文本。

客户数据是中国本土模拟数据，仅用于演示，不能视为真实个人信息。

## 6. 安装后校验

安装脚本末尾会输出各表实际行数。连接 SH 后可执行以下查询：

```sql
SELECT MIN(time_id) AS 最早销售日期,
       MAX(time_id) AS 最晚销售日期,
       COUNT(*)     AS 销售行数
FROM sales;

SELECT calendar_year AS 年份,
       COUNT(*) AS 销售行数
FROM sales s
JOIN times t ON t.time_id = s.time_id
GROUP BY calendar_year
ORDER BY calendar_year;

SELECT table_name, partition_name, high_value
FROM user_tab_partitions
WHERE table_name IN ('SALES', 'COSTS')
ORDER BY table_name, partition_position;
```

以下两个异常行数应均为 **0**，无促销记录也参与日期校验：

```sql
SELECT 'SALES' AS table_name, COUNT(*) AS invalid_rows
FROM sales s LEFT JOIN promotions p ON p.promo_id = s.promo_id
WHERE p.promo_id IS NULL
   OR s.time_id NOT BETWEEN p.promo_begin_date AND p.promo_end_date
UNION ALL
SELECT 'COSTS', COUNT(*)
FROM costs c LEFT JOIN promotions p ON p.promo_id = c.promo_id
WHERE p.promo_id IS NULL
   OR c.time_id NOT BETWEEN p.promo_begin_date AND p.promo_end_date;
```

生成器会自动执行上述业务校验，并检查促销区间、日期覆盖和每日销售行数；失败时抛出错误，而不是仅打印行数后报告成功。开发回归测试见 `tests/README.md`。

可检查中文时间维度：

```sql
SELECT time_id, day_name, calendar_month_desc, calendar_quarter_desc
FROM times
ORDER BY time_id
FETCH FIRST 10 ROWS ONLY;
```

## 7. 卸载

以具备删除用户权限的账号连接，并在 `sales_history_cn/sales_history` 目录执行：

```sql
@sh_uninstall.sql
```

该操作会删除整个 SH 用户及其全部对象。若需要保留结果，请先按本地运维规范完成 Data Pump 导出或备份。

## 8. 常见问题

| 现象 | 处理建议 |
| --- | --- |
| `RANGE` 参数报错 | 两个日期都必须填写，并严格使用 `YYYY-MM-DD`；起始日期不得晚于结束日期。 |
| 追加未生成数据 | 目标结束日期未晚于 `TIMES` 当前最大日期；这是安全跳过，不会产生重复数据。 |
| 追加提示 `TIMES` 被其他会话修改 | 等待另一项追加完成后重试；同一时间只允许一个追加会话。 |
| 需要重建已有日期 | `sh_append.sql` 故意不支持；请先备份，并使用人工审核的重建流程。 |
| 中文显示乱码 | 确认数据库字符集为 `AL32UTF8`，并使用支持 UTF-8 的终端。 |
| 找不到 CSV 文件 | 必须从包含 `customers.csv` 和 `supplementary_demographics.csv` 的 `sales_history_cn/sales_history` 目录执行安装。`promotions.csv` 已不参与装载。 |
| 生成数据比预期少 | 完整年度约为 200,000 行，不完整年份会按实际天数等比例生成。 |
| 表空间不足或执行较慢 | 每完整年会额外增加约 20 万条销售及对应成本数据，并创建本地索引；请增加表空间并预留足够的加载时间。 |
