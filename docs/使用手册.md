# SH 中文化样例数据使用手册

本项目用于个人测试和 PoC：在保留 Oracle SH 标准英文对象名的前提下，装载中文化维度数据，并按安装参数生成可复现的销售历史增量。

## 1. 前置条件

- Oracle Database 19c 或更高版本，数据库字符集为 `AL32UTF8`。
- SQLcl 26.1.2.0 或更高版本。
- 使用具备创建、删除用户权限的账号连接，例如 `SYSTEM` 或 `ADMIN`。
- 从仓库内的 `sales_history_cn/sales_history` 目录执行脚本；该目录下的 CSV 文件必须完整保留。

> 注意：若输入 `YES` 覆盖已有 SH 模式，安装脚本会执行 `DROP USER SH CASCADE`。这会永久移除该用户及其对象，请勿对承载业务数据的 SH 用户执行。

## 2. 安装

在终端中进入脚本目录并连接目标数据库：

```bash
cd sales_history_cn/sales_history
sql system@//db-host:1521/service_name
```

在 SQLcl 中运行：

```sql
@sh_install.sql
```

安装依次询问 SH 密码、表空间、生成参数和是否覆盖已有 SH 模式。脚本会在当前目录生成 `sh_install.log`。

### 默认方式：最近 N 个完整自然年加今年截至当天

输入示例：

```text
生成模式 [RECENT|RANGE] [RECENT]: RECENT
RECENT 模式的完整自然年数 [3]: 3
RANGE 模式起始日期 (YYYY-MM-DD，可留空):
RANGE 模式结束日期 (YYYY-MM-DD，可留空):
```

其中“当天”取目标数据库服务器的 `SYSDATE`。例如服务器日期为 `2026-09-09`、N 为 3 时，请求范围为 `2023-01-01` 至 `2026-09-09`。

### 自定义方式：指定起止日期

输入示例：

```text
生成模式 [RECENT|RANGE] [RECENT]: RANGE
RECENT 模式的完整自然年数 [3]: 3
RANGE 模式起始日期 (YYYY-MM-DD，可留空): 2025-07-01
RANGE 模式结束日期 (YYYY-MM-DD，可留空): 2030-12-31
```

`RANGE` 的起止日期均包含在范围内，可指定未来日期；`RECENT` 模式下 `generation_start` 和 `generation_end` 会被忽略。

## 3. 生成规则

- 原始 CSV 先装载为基线；新增数据只从现有 `SALES` 最大日期的次日开始生成，不回写历史事实数据。
- 请求起点早于基线最大日期时会自动截断。安装输出会显示“请求范围”“现有销售数据截至”和“实际新增范围”。
- 每个完整自然年生成约 200,000 条 `SALES`，不完整年度按实际天数比例生成；同时为新增销售生成匹配的 `COSTS` 行。
- 固定随机种子为 `20260909`。在 CSV、脚本版本和输入参数一致时，生成的新增事实数据一致。
- `TIMES` 使用中国自然日历：周一为首日，周日为周结束日；财年、财月、财季等同自然年口径。时间文本格式示例：`2026年09月`、`2026年Q3`、`星期一`。
- `SALES` 和 `COSTS` 使用按年自动扩展的 interval 分区，因此生成到未来年份不需要再修改建表 DDL。

## 4. 中文化范围

数据库对象名保持 Oracle SH 的英文命名，以兼容标准示例 SQL。装载后，以下展示数据会被中文化：

- 国家和区域名称；客户姓名、地址、电话、邮箱、收入与婚姻状态。
- 产品的单位、包装、状态和汇总描述。
- 促销名称、类别、子类别与汇总描述。
- 补充人口统计中的教育、职业、家庭规模和备注。
- `TIMES` 的星期、月、季及财务期间文本。

客户数据是中国本土模拟数据，仅用于演示，不能视为真实个人信息。

## 5. 安装后校验

安装脚本末尾会输出各表实际行数。连接 SH 后可执行以下查询：

```sql
SELECT MIN(time_id) AS 最早销售日期,
       MAX(time_id) AS 最晚销售日期,
       COUNT(*)     AS 销售行数
FROM sales;

SELECT calendar_year AS 年份,
       COUNT(*) AS 销售行数
FROM sales s
JOIN times t ON t.time_id = s.time_id
GROUP BY calendar_year
ORDER BY calendar_year;

SELECT table_name, partition_name, high_value
FROM user_tab_partitions
WHERE table_name IN ('SALES', 'COSTS')
ORDER BY table_name, partition_position;
```

可检查中文时间维度：

```sql
SELECT time_id, day_name, calendar_month_desc, calendar_quarter_desc
FROM times
ORDER BY time_id
FETCH FIRST 10 ROWS ONLY;
```

## 6. 卸载

以具备删除用户权限的账号连接，并在 `sales_history_cn/sales_history` 目录执行：

```sql
@sh_uninstall.sql
```

该操作会删除整个 SH 用户及其全部对象。若需要保留结果，请先按本地运维规范完成 Data Pump 导出或备份。

## 7. 常见问题

| 现象 | 处理建议 |
| --- | --- |
| `RANGE` 参数报错 | 两个日期都必须填写，并严格使用 `YYYY-MM-DD`；起始日期不得晚于结束日期。 |
| 中文显示乱码 | 确认数据库字符集为 `AL32UTF8`，并使用支持 UTF-8 的终端。 |
| 找不到 CSV 文件 | 必须从包含 `sales.csv`、`costs.csv`、`times.csv` 等文件的 `sales_history_cn/sales_history` 目录执行安装。 |
| 生成数据比预期少 | 只会生成基线最大销售日期后的部分；请查看安装输出中的实际新增范围。 |
| 表空间不足或执行较慢 | 每完整年会额外增加约 20 万条销售及对应成本数据，并创建本地索引；请增加表空间并预留足够的加载时间。 |
